## Design

- 10 source samples × 1 CE-MS/MS run each (label-free) = **10 rows**.
- Groups: 2 Normal Control (`Healthy1`, `Healthy2`) and 8 CKD/IgAN (`CKD1`–`CKD8`).
- `comment[data file]` uses deposited vendor RAW names (`Healthy1.raw` … `CKD8.raw`), not CE run IDs (`200616L000001` …) and not `.mgf`.
- Factor: `factor value[disease]`.

## Templates

`ms-proteomics v1.1.0` + `human v1.1.0`.

- MS technology, *Homo sapiens* urine, DDA CE-MS/MS.
- **No `clinical-metadata`**: GFR, proteinuria, and MAP are in the depositor sheet but are not required clinical-template columns, and no treatment/compound fields were annotated.
- **No `dia-acquisition`**: data-dependent HCD top 20.
- **No `cell-lines`**: urine, not cultured cells.

## Honest gaps

- Ancestry not provided.
- Spreadsheet GFR, proteinuria (g/day), and MAP were not added as SDRF columns (not TERMS fields for the chosen templates).
- PRIDE instrument string was generic; Velos term is from the paper/protocol, not from archive instrument metadata.
- Protocol also mentions MS/MS scanning 350–1500 amu vs full-scan 300–2000 m/z; `comment[ms min mz]` / `comment[ms max mz]` were omitted rather than picking one range.
- Biological replicate is `1` for every distinct donor (not a 1–10 numbering across individuals).

## Validation

```
parse_sdrf validate-sdrf \
  --sdrf_file datasets/PXD039829/PXD039829.sdrf.tsv \
  --use_ols_cache_only \
  --template ms-proteomics \
  --template human
```

Result: **0 errors**. One warning from `--use_ols_cache_only`:

```
WARNING: Accession 'pride:0000627' in column 'comment[proteomics data acquisition method]' is not under parent term 'PRIDE:0000659'
```

OLS shows `PRIDE:0000627` (`Data-dependent acquisition`) as a child of `PRIDE:0000659`. This is treated as a cache-parent warning, not a term error. Value kept as `NT=Data-dependent acquisition;AC=PRIDE:0000627`.
