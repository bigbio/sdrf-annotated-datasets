## ±PNGase modelling

The submitter sheet recycled biological replicate `1,2,3` across genotypes and treated `*_P.raw` as different `source name` values (`…_PNGase_F`). That is wrong: PRIDE sample processing split each membrane prep onto S-Trap columns and digested **with or without PNGase F**.

Rebuilt design:

- **`source name`**: genotype×bio for the untreated digest (e.g. `WT_bio1`); PNGase F digest of that membrane prep is a processed aliquot named `{source}_PNGaseF` (e.g. `WT_bio1_PNGaseF`) so coordinates stay unique
- **`characteristics[biological replicate]`** = `_1`/`_2`/`_3` from the filename (1/2/3 within each genotype)
- **`factor value[enzyme]`** = `untreated` vs `PNGase F` (digestion contrast, not a technical reinjection)
- **`comment[technical replicate]`** = `1` on every row (PNGase is not a technical replicate)
- **`assay name`** = RAW stem (unique)
- **`factor value[cell line]`** copies `characteristics[cell line]` (`Pro-5 cell` / `Lec5` / `Lec9`)
- **`factor value[treatment]`** = `untreated` vs `DHRSX` (human DHRSX complementation on Lec5/Lec9). WT and non-complemented Lec lines are `untreated`. Filenames do not say empty vector for WT (`01_WT_*`); the submitter sheet used `Prop_5_EV` — EV was **not** copied onto WT.
